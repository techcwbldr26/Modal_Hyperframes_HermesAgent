SECTION 02

Framework vs Harness

Two paradigms for building AI agents

Frameworks

Build from parts

  • LangChain, AutoGen
  • Manual wiring of chains & retrievers
  • You assemble the pipeline
  • Building blocks, not a working agent

Harnesses

Pre-wired & ready

  • Claude Code, Cursor
  • Pre-wired execution loop
  • Targets user goals directly
  • Industry is converging here
Frameworks give you parts. Harnesses give you a working agent.
SECTION 03

The Execution Loop

The heartbeat of every agent harness

The While Loop

Initialize
Read Context
Call LLM
Evaluate Output
Branch

No tool calls → final answer · tool calls → execute → observe → loop

Two Exit Conditions

  • Clean exit: model returns final answer
  • Hard stop: max iterations exceeded
  • Each turn appends tool observations
  • Bounded by a max iteration counter
Read → Call → Inspect → Act → Repeat. Two ways out.

What Gets Preserved

SECTION 05

Tools, Skills & Permission Gating

How the harness controls what tools may run

Tool Registry

  • Tools registered by name + metadata
  • LLM addresses tools by name only
  • Registry decouples definition from execution
  • Examples: view_file, write_file, run_bash

Permission Tiers

  • Read-only: view files, search
  • Workspace: write within project dir
  • Full: any command, any path
  • Intercept before execute — never run blindly
The harness intercepts every tool call before it runs.
SECTION 06

Sub-Agent Delegation

Spawning specialist agents for exploration and verification

Explorer Sub-Agent

  • Spawned with isolated session
  • Restricted tools (search, read)
  • Runs search turns
  • Returns findings summary, not raw logs

Verifier Sub-Agent

  • Separate isolated session
  • Restricted to pytest only
  • Runs the test suite
  • Returns pass/fail result to parent
Sub-agents return summaries, not raw logs — protecting the parent's context.
SECTION 07

Session Persistence & Prompt Assembly

How agents remember and rebuild context

Event Log (JSONL)

  • Every turn recorded as a discrete event
  • USER_INPUT → MODEL_CALL → TOOL_RESULT
  • Append-only JSONL stream
  • Compaction events flushed to disk

Three-Layer Prompt Rebuild

  • Layer 1: Static base harness instructions
  • Layer 2: Injected AGENTS.md config
  • Layer 3: Replayed compacted history
  • Assembled fresh every turn
Log everything. Rebuild the prompt from three layers each turn.
SECTION 08

Hooks, Permissions & Safety

The multi-stage safety pipeline

Pre-Tool Hooks

  • Intercept before execution
  • Allow → run the tool
  • Deny → block with error
  • Modify → rewrite the command

Post-Tool & Interactive Approval

  • Post-tool hooks: audit every result
  • Destructive commands escalate to user
  • Interactive approval prompt: approve or deny
  • Audit log injected back into context
Never execute directly — traverse the safety pipeline first.
SECTION 09

Research Insights

What Tsinghua's NLAH study tells us about harness design

Module Ablation Results

  • Self-Evolution Attempt Loop: +4.8 SWE-bench ✓
  • Evaluation Verifiers: −0.8 SWE-bench ✗
  • Multi-Candidate Search: −2.4 SWE-bench ✗
  • Only Self-Evolution consistently helps

Harness Design Principle

  • Narrowing attempt loop > broadening search
  • Verifiers and search hurt performance
  • Fold Self-Evolution into core rule
  • Drop what doesn't help
Narrowing the attempt loop beats broadening the search space.
